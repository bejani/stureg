# StuReg

سامانه‌ی وب PHP/MySQL برای جمع‌آوری رضایت‌محور اطلاعات دانش‌آموزان، ارتباط پیامکی داخلی با مدیر و علامت‌گذاری موارد نیازمند پیگیری مشاور مدرسه.

## امکانات نسخه اول

- ورود دانش‌آموز با شماره موبایل و رمز اختصاصی که مدیر ایجاد می‌کند.
- فرم اطلاعات فردی، والدین، تماس اضطراری و سلامت با ثبت زمان رضایت.
- پنل دانش‌آموز برای ویرایش اطلاعات و ارسال/دریافت پیام.
- پنل مدیر برای فهرست دانش‌آموزان، مشاهده پرونده، دیدن پیام‌ها، پاسخ‌گویی و علامت «نیازمند پیگیری/ارجاع».
- استفاده از PDO، کوئری‌های prepared، هش رمز عبور، CSRF و escape خروجی.
- خروجی پشتیبان JSON و CSV سازگار با Excel از پنل مدیر؛ خروجی فقط برای مدیر واردشده در دسترس است و شامل password_hash نمی‌شود.

## خروجی و پشتیبان‌گیری

پس از ورود مدیر، در بالای پنل دو گزینه وجود دارد: «خروجی Excel» که فایل CSV UTF-8 قابل بازشدن در Excel ایجاد می‌کند و «پشتیبان JSON» که پرونده‌های دانش‌آموزان، پیام‌ها و زمان خروجی را ذخیره می‌کند. این فایل‌ها حاوی اطلاعات حساس هستند؛ پس از دانلود آن‌ها را در فضای امن نگه‌داری کنید و در صورت نیاز از روی رایانه عمومی حذف کنید.

## نسخه ۲.۱

نسخه ۲.۱ داشبورد آماری، جست‌وجو و فیلتر بر اساس نام، موبایل، پایه و وضعیت، وضعیت پیگیری پرونده، یادداشت داخلی مدیر، شمارنده پیام‌های خوانده‌نشده و تغییر رمز عبور دانش‌آموز را اضافه می‌کند. برای دیتابیس‌های موجود، migration `migrations/2026_09_v2_1_followup.sql` را فقط یک‌بار اجرا کنید. در نصب تازه، `schema.sql` شامل این ساختار است.

## نسخه ۲.۲

نسخه ۲.۲ نقش محدود «مشاور»، رضایت‌های جداگانه برای آموزش، سلامت، تماس با سرپرست و ارجاع مشاوره‌ای، دسته‌بندی و فوریت پیام‌ها و ثبت گزارش فعالیت‌های حساس را اضافه می‌کند. مدیر می‌تواند حساب مشاور بسازد؛ مشاور می‌تواند پرونده‌ها و پیام‌های لازم را ببیند اما به اطلاعات حساس، خروجی کامل، ساخت کاربر، تغییر وضعیت و یادداشت داخلی دسترسی ندارد. برای دیتابیس موجود، migration `migrations/2026_09_v2_2_roles_consent_audit.sql` را فقط یک‌بار اجرا کنید. پس از migration، حساب مشاور را از پنل مدیر بسازید.

## نسخه ۲.۳

نسخه ۲.۳ مدیریت سال‌های تحصیلی، ورود گروهی دانش‌آموزان با CSV، ارجاع رسمی پرونده به مشاور، صفحه گزارش فعالیت‌ها و خروجی‌های فیلترشده را اضافه می‌کند. برای دیتابیس موجود، migration `migrations/2026_09_v2_3_year_referrals.sql` را فقط یک‌بار اجرا کنید. فایل CSV ورود گروهی باید ستون‌های `name,mobile,password` را داشته باشد. قبل از ارجاع، حداقل یک حساب مشاور بسازید.

## راه‌اندازی محلی

1. PHP 8.1+، MySQL 5.7+/MariaDB و وب‌سرور Apache نصب کنید.
2. دیتابیس را بسازید: `mysql -u root -p < schema.sql`
3. فایل `includes/config.local.example.php` را با نام `includes/config.local.php` کپی کنید و مقادیر محیط خود را در آن قرار دهید. فایل `config.local.php` در `.gitignore` است و نباید وارد GitHub شود.
4. اگر پروژه در آدرس `http://localhost/stureg` اجرا می‌شود، مقدار پیش‌فرض `APP_BASE_PATH` در `includes/config.php` درست است. اگر پروژه مستقیماً در ریشه دامنه نصب شد، آن را به `''` تغییر دهید.
5. رمز هش‌شده‌ی مدیر بسازید: `php -r "echo password_hash('رمز-قوی', PASSWORD_DEFAULT), PHP_EOL;"`
6. دستور INSERT کامنت‌شده در `schema.sql` را با هش تولیدشده اجرا کنید. برای هر دانش‌آموز نیز یک رکورد در جدول `users` بسازید؛ نقش باید `student` باشد.
7. از ریشه پروژه اجرا کنید: `php -S localhost:8000` و سپس `http://localhost:8000` را باز کنید.

## انتقال به InfinityFree

فایل‌ها را در `htdocs` آپلود کنید، دیتابیس و کاربر MySQL را در کنترل‌پنل بسازید و `schema.sql` را از طریق phpMyAdmin وارد کنید. سپس `includes/config.local.example.php` را روی کامپیوتر به `includes/config.local.php` کپی کنید، مقادیر اتصال InfinityFree را وارد کنید و همین فایل را جداگانه در `htdocs/includes/` آپلود کنید. در InfinityFree مقدار `app_env` باید `production` و `app_base_path` باید `''` باشد. فایل `config.local.php` نباید در GitHub commit شود.

فایل `includes/config.php` عمومی و مشترک باقی می‌ماند؛ بنابراین اجرای `git pull` تنظیمات دیتابیس محلی یا InfinityFree را بازنویسی نمی‌کند. اگر `config.local.php` وجود نداشته باشد، مقادیر پیش‌فرض برای Laragon با دیتابیس `stureg` و کاربر `root` استفاده می‌شوند.

## به‌روزرسانی فرم شناخت دانش‌آموز

برای نصب روی دیتابیس موجود، migrationهای پوشه `migrations` را به‌ترتیب در دیتابیس `stureg` اجرا کنید. migration دوم فیلدهای آموزشی، علایق، شیوه ارتباط، حال عمومی، امکانات مطالعه و درخواست حمایت را اضافه می‌کند. این بخش‌ها اختیاری هستند و گزینه «ترجیح می‌دهم پاسخ ندهم» نیز در موارد حساس وجود دارد.

## ملاحظات حریم خصوصی

اطلاعات سلامت و تماس اضطراری داده‌ی حساس است. قبل از استفاده واقعی، متن رضایت را با سیاست مدرسه/قوانین محل تطبیق دهید، دسترسی مدیر را محدود کنید، رمزها را قوی و HTTPS را فعال کنید، پشتیبان‌گیری امن و سیاست حذف/نگهداری داده داشته باشید. این نسخه ابزار پیام‌رسان داخلی دارد و جایگزین پروتکل رسمی ارجاع اورژانسی یا مشاوره نیست.

## ساخت حساب‌ها

این نسخه برای کاهش ریسک، ثبت‌نام عمومی ندارد. مدیر باید حساب دانش‌آموز را با رمز موقت تولید و از مسیر امن در اختیار او بگذارد؛ در نسخه بعدی می‌توان تغییر رمز اجباری، بازیابی رمز و ورود دومرحله‌ای را افزود.
